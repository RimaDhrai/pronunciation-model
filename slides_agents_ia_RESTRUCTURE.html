Pilier 1

Prompt Engineering

Structurer les instructions pour un raisonnement prévisible

Structure d'un Prompt Efficace

🎯
Role
Définir le rôle de l'agent (ex: "Tu es un coach de prononciation")
📋
Objectif
Clarifier la tâche précise (ex: "Générer des phrases pour pratiquer le son /ʃ/")
📐
Contraintes
Limites (longueur, format, complexité) pour contrôler la sortie
📤
Format de sortie
JSON, XML, ou texte structuré pour le parsing fiable
""" Role: Spécialiste en prononciation Objectif: Générer 5 phrases pour pratiquer le phonème /ʃ/ pour niveau B1 Contraintes: - Longueur: 50-80 caractères - Complexité: B1 CECRL - Format: JSON Exemple: { "phrases": [ {"text": "Le chat dort", "phonemes": ["/ʃ/"]}, ] } """

Pilier 2

Context Engineering

Gestion intelligente de la mémoire et du contexte

💾 Mémoire Court Terme (Session)

Contexte conversationnel actuel, état de la session en cours.

📌 State JSON - Profil utilisateur
🔄 CheckPointer - Sauvegarde LangGraph
💬 Chat History - Messages récents

🧠 Mémoire Long Terme (Persistance)

Historique persistant, progression de l'utilisateur, patterns d'erreurs.

📊 PostgreSQL - BD relationnelle
📈 Stats XP - Progression utilisateur
🎯 Weak Words - Points faibles

🔀 Pipeline de Context Enrichment

Avant chaque appel au LLM, enrichissement du contexte avec données pertinentes :

Profil (niveau CECRL, langue)
Historique (derniers sons pratiqués)
Erreurs (sons mal prononcés)
Objectif (cible pédagogique)

Pilier 5

Agent Loop

La boucle autonome de perception-décision-action

👁️
Perception
→
🧠
Raisonnement
→
⚡
Action
→
📊
Feedback
↻

📥 Perception

L'agent reçoit une requête utilisateur et enrichit son contexte avec données pertinentes (historique, profil, objectif).

🧠 Raisonnement

Le LLM analyse le contexte, décide quelle action prendre (appel outil, réponse directe, routing).

⚡ Action

Exécution de la décision : appel API, requête DB, génération de contenu, affichage à l'utilisateur.

📊 Feedback

L'agent observe le résultat, met à jour son état, et continue la boucle si nécessaire.

Pilier 6

Safety

Garde-fou et validations pour éviter les dérives

🚦 Limites du Contexte

Empêcher que le contexte ne devienne trop grand (explosion tokens/latence).

🔒 Max tokens session
🗑️ Éviction du contexte ancien
⏰ TTL (Time To Live) messages

🛡️ Validations de Sortie

Vérifier que les réponses du LLM respectent les contraintes métier.

✅ JSON parsing strict
🔍 Validation schéma
⚠️ Fallback en cas erreur

🔐 Rate Limiting & DoS

Prévenir l'abus de ressources par l'agent ou les utilisateurs.

📊 Limite requêtes/min
💰 Budget tokens LLM
⏳ Timeout actions

🎯 Vérification de Pertinence

S'assurer que les actions sont appropriées au contexte et à l'utilisateur.

🎓 Niveau adapté à l'apprenant
🔄 Pas de boucle infinie
👤 Authentification + autorisation
