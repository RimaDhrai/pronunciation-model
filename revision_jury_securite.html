Sécurité de l'agent — 3 niveaux

Fiche de révision SpeakCoach · Réponse honnête pour doctorante IA

Niveau 1
🔐 Sécurité système
  • Keycloak + JWT OAuth2
  • Rôles admin / collaborateur
  • CORS restreint (Spring)
  • Sessions stateless
  • Rate limiting (roadmap)
Niveau 2
🤖 Sécurité agentique
  • Routage sans LLM (switch mode)
  • StateGraph à nœuds fixes
  • Tools fixes (Whisper, TTS, eval)
  • 20 steps max · TTL 1h · timeouts
  • Historique 20 msgs · contexte 4
  • Tools dynamiques arbitraires
Niveau 3
🧠 Sécurité LLM
  • System prompt contraint (CECRL)
  • Quick responses (≤12 car, exact)
  • Fallbacks si échec / timeout
  • Validation DTO (mode, score, phrase)
  • Anti-jailbreak / guardrails model
  • Modération toxicité / PII

Révision jury · Q&R

Questions fréquentes — réponses courtes

À réciter en 20–30 secondes chacune

❓ Ton agent est-il sécurisé ?
Partiellement, par design restrictif. Domaine restreint (coaching vocal), pas d'agent généraliste. Guardrails contenu = roadmap.
❓ Prompt injection ?
Surface réduite : pas de LLM-router, tools fixes, prompt verrouillé. Pas de classifieur anti-injection dédié. Pire cas = texte inapproprié, pas action système.
❓ Actions dangereuses ?
Non. Pas de ReAct libre. Seulement STT, TTS, scoring phonétique, génération texte pédagogique. Pas de SQL/file/HTTP arbitraire.
❓ Boucles infinies ?
StateGraph borné. Chatbot = 2 nœuds linéaires. Test = 20 steps. Timeouts 25–55s. TTL session 1h.
❓ Hallucinations LLM ?
Prompt + fallbacks + post-traitement TTS. PhraseTaxonomy si LLM down. Pas de modération sémantique auto.
❓ LangGraph = sécurité ?
Non, orchestration. LangGraph borne le comportement (état, nœuds). Guardrails contenu = couche au-dessus, complémentaire.
❓ Session vs auth ?
JWT Keycloak sur API. Session agent = UUID. Limitation MVP : lier obligatoirement session ↔ user JWT en prod.
❓ Exemple d'attaque ?
« Ignore tes instructions » → le LLM peut céder partiellement. Défense : aucun tool dangereux disponible. Mitigation future : output filter + guardrail model.
